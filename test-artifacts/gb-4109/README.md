# 容量台账验证 · gb-4109

针对"检验库目标行上限"能力的场景验证。直接在本机 Python 运行（SQLite 落盘于本目录，Redis 队列以内存假件替代，不污染源码树）：

```sh
python3 test-artifacts/gb-4109/run_tests.py
```

覆盖场景：

| 用例 | 验证点 |
|---|---|
| T1 | 受理即预留；容量不足拒绝并说明差多少行 |
| T2 | 坏行与同键重复行不占额度 |
| T3 | 仅剩一份时并发争抢，恰有一个受理成功，其余拒绝且不超额 |
| T4 | 落库时预留转实占，台账与目标表实际行数一致 |
| T5 | 取消归还额度 |
| T6 | 执行失败归还额度 |
| T7 | 执行失联回收预留；迟到的旧执行者回来不能再落库 |
| T8 | 重试不重复占额（释放/提交/回收/恢复均幂等） |
| T9 | 满库恢复：等量替换净增 0 放行；新受理拒绝；上限校验 |
| T10 | API 冒烟：角色权限、拒绝报文、容量页数据 |
